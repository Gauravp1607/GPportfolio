    Featured case study

    From Marathi lyrics to Indian Sargam

    A multi-stage audio intelligence pipeline for separating vocals, recognizing Devanagari lyrics, detecting polyphonic harmonium notes, and presenting the synchronized result.

    01

    The challenge

    Traditional transcription asks a musician to listen repeatedly, identify Marathi lyrics, recognize overlapping harmonium notes, and align both by hand. HarmoLyric AI brings those steps into one repeatable workflow.

    02

    The approach

    Audio is standardized to 16 kHz mono, separated with Spleeter, transcribed with Marathi Whisper timestamps, and transformed with Librosa features. A CNN + Bi-LSTM model then performs multi-label pitch-class detection.

    03

    The result

    Detected Western pitch classes are mapped to Sargam from the user's selected Sa, smoothed into meaningful events, synchronized with lyric timestamps, and exported as JSON or CSV for the dashboard.

    Results & accuracy

    Designed for polyphonic musical detail

    The custom harmonium dataset contains more than 21,000 samples spanning isolated notes, triads, and multiple octaves. The balanced 12-class model regularly reached over 95% confidence on clean single-note inputs, with a 50% activation threshold for multi-label predictions.

    • 12pitch classes
    • 21k+audio samples
    • 0.12sshort-event cleanup
    • 8.33%balanced class share

    How it was implemented

    End-to-end build method

    The system is organized as a queue-based Flask application. Each stage produces a structured output that becomes the input for the next stage, keeping audio processing, machine learning, and presentation logic separate.

    1. 01

      Accept and validate the upload

      Flask receives the audio file and the user's base note, Sa. The application validates the extension, stores the upload, and creates a job record instead of blocking the browser.

      Flask · HTML5 · Jinja2
    2. 02

      Queue the heavy work

      Redis stores the job state and RQ sends the processing task to a background worker. This keeps Spleeter, Whisper, and model inference outside the normal request-response cycle.

      Redis · RQ · Python
    3. 03

      Standardize the audio

      Pydub converts WAV, MP3, M4A, and FLAC inputs into normalized 16 kHz mono WAV audio so every downstream model receives a predictable signal.

      Pydub · WAV · 16 kHz mono
    4. 04

      Separate vocals and harmonium

      Spleeter splits the mixed recording into vocal and accompaniment stems. The vocal stem is reserved for Marathi speech recognition, while the harmonium stem is analyzed for musical notes.

      Spleeter · source separation
    5. 05

      Transcribe Marathi lyrics

      Whisper processes the vocal stem and returns Devanagari text with start and end timestamps. Grapheme-aware text handling preserves Marathi matras and conjunct characters for correct display.

      OpenAI Whisper · Marathi ASR
    6. 06

      Build the musical representation

      Librosa slices the harmonium stem using lyric intervals and extracts mel-spectrogram, chromagram, and pitch-cents features. These are resized and stacked into a three-channel tensor for the model.

      Librosa · NumPy · SpecStacker
    7. 07

      Predict and smooth pitch classes

      The CRNN combines CNN layers for spectral patterns with a Bi-LSTM for time context. Sigmoid outputs allow several notes to be active together; thresholding and event merging remove brief prediction flicker.

      TensorFlow / Keras · CNN · Bi-LSTM
    8. 08

      Map, synchronize, and export

      Detected Western pitch classes are converted to Sargam using semitone distance from the selected Sa. Lyrics, notes, and timestamps are joined into JSON, converted to CSV, and rendered in the dashboard.

      Sargam mapping · JSON · CSV · Jinja2

    Methodology

    Why this approach works

    Audio signal processing

    Mel-spectrograms describe frequency energy over time, chromagrams capture pitch-class energy, and cents values retain finer pitch movement.

    Multi-label classification

    Harmonium can produce simultaneous notes, so sigmoid outputs are used instead of softmax. A threshold activates every pitch class that is present.

    Temporal synchronization

    Whisper timestamps define lyric windows, while note events are merged and aligned to those same intervals for a readable transcription.

    Data improvement

    More than 21,000 samples are balanced across 12 pitch classes and expanded with pitch shifting, time stretching, and controlled noise.

    Results & accuracy

    Measured performance on harmonium data

    HarmoLyric AI was evaluated using a custom harmonium dataset containing more than 21,000 audio samples, including isolated notes and polyphonic triads across different harmonium octaves.

    Dataset balance

    The 12 chromatic pitch classes were balanced to approximately 8.33% each in the final distribution.

    Clean-note confidence

    The correct pitch class regularly produced more than 0.95 confidence on clean, isolated notes.

    Activation threshold

    A 0.50 confidence threshold determined whether a pitch class was active.

    380 detections

    210 detections

    Ga (Melody)

    150 detections

    120 detections

    Because the model uses multi-label classification, it detected simultaneous notes such as the three notes of a C-Major triad instead of selecting only the loudest note.

    Temporal post-processing used merge_and_threshold_events to merge consecutive identical predictions and remove events shorter than approximately 0.12 seconds. This reduced frame-level flickering and produced smoother note sequences.

    From a business question to a trusted answer

    QueryGenie is an AI-powered SQL and NLP assistant that lets business users query relational data in natural language while the system handles schema context, SQL generation, validation, execution, and explanation.

    01

    The problem

    Managers often need business answers but should not have to learn table names, joins, aggregation functions, or SQL syntax to find them.

    02

    The approach

    A Flask REST API sends the question and database schema context to an AI model, validates the generated read-only SQL, and executes it against the real database.

    03

    The outcome

    Query results are processed and turned into a clear business explanation, so the user receives an answer grounded in database data rather than an unsupported AI guess.

      Chatbot UI · Natural language
    2. 02

      Send the request through Flask

      The frontend sends the question to a Flask REST endpoint. The backend becomes the controlled communication layer between the UI, AI model, and database.

      Python · Flask · REST API
    3. 03

      Ground the AI in the schema

      The prompt includes relevant tables and columns, such as product, region, sales, quantity, and order date, so the model can connect user language to real database fields.

      Schema context · Prompt engineering
    4. 04

      Generate SQL from intent

      OpenAI API · NLP-to-SQL
    5. 05

      Validate before execution

    6. 06

      JSON · Chatbot interface

    Research case study

    Deep learning and generative AI for music

    This project is a systematic review of music-generation research, not one single application. It compares music representations, datasets, model families, generation tasks, and evaluation methods across multiple studies.

    01

    The research question

    How can deep learning learn musical structure and generate new melodies, performances, audio, or multi-track compositions from existing music?

    02

    The comparison

    The review studies MIDI, spectrogram, and raw-waveform inputs alongside RNNs, LSTMs, GRUs, GANs, VAEs, Transformers, diffusion, and reinforcement learning.

    03

    The conclusion

    MIDI is a strong structured representation, while MIDI + LSTM, GAN approaches, MusicGen, MusicLM, and symbolic diffusion each perform well for different generation goals.

    How the research is organized

    From music data to evaluated generation

    The review compares branches of a common pipeline rather than claiming one universal system. Each study chooses a representation and model based on the generation task.

    1. 01

      Choose the music representation

      MIDI stores notes, pitch, timing, duration, velocity, instruments, and chords. Spectrograms represent time, frequency, and intensity, while raw waveforms preserve the audio signal directly.

      MIDI · Spectrogram · Raw waveform
    2. 02

      Prepare features or tokens

      The selected representation is converted into numerical sequences, image-like spectrograms, or audio tokens that a model can learn from.

      MIDI processing · FFT · Spectrogram processing
    3. 03

      Compare sequence models

      RNN, LSTM, and GRU models learn temporal relationships. Transformers use self-attention to connect distant positions and support longer musical context.

      RNN · LSTM · GRU · Transformer
    4. 04

      Compare generative models

      GANs learn through generator-discriminator competition, VAEs learn a controllable latent space, normalizing flows transform probability distributions, and diffusion models learn denoising.

      GAN · VAE · Flow · Diffusion
    5. 05

      Generate the music

      Autoregressive systems generate one element at a time. WaveNet works with raw audio, while MusicGen and MusicLM use language-model-style conditioning for text, melody, or semantic and acoustic tokens.

      WaveNet · MusicGen · MusicLM · EnCodec
    6. 06

      Evaluate multiple dimensions

      Generated music is compared using distribution metrics, pitch and duration consistency, prompt relevance, musical structure, creativity, diversity, and human listener ratings.

      FID · FAD · KL · CLAP · MMD · Human evaluation

    Technologies and methodologies

    What the review studies

    Symbolic generation

    MIDI is compact and preserves musical structure, making it suitable for sequence models such as LSTM and symbolic diffusion systems.

    Audio generation

    Spectrogram and raw-waveform approaches study how models can generate playable audio, including SpecGAN and WaveGAN comparisons.

    Conditional generation

    MusicGen and MusicLM study text-conditioned, melody-conditioned, and hierarchical token-based generation.

    Reinforcement learning

    Bach2Bach and RE-RL Tuner use reward-based learning to encourage musical behavior, structure, and coherence.

    Research datasets

    The reviewed studies use datasets including MagnaTagATune, YouTube Piano, MusicCaps, MAESTRO, VoxCeleb2, FreeSound, Looperman, pop MIDI, and Bach music.

    Evaluation methodology

    There is no single accuracy score for generative music. FID, FAD, KL, CLAP, Inception Score, MMD, pitch consistency, duration consistency, and human ratings measure different properties.

    Reported results

    How performance is interpreted

    The review compares results within their original studies. These values should not be treated as one overall accuracy for the entire project.

    Symbolic diffusion

    Pitch consistency: 99%. Duration consistency: 96% unconditional and 97% for infilling. Reported FID: 0.0166. Reported MMD: 0.0018.

    WaveGAN

    Reported Inception Score: 4.67 ± 0.01. Human recognition: 58%. Human quality rating: 2.3/5.

    SpecGAN

    Reported Inception Score: 3.71. Human recognition: 66%. Human quality rating: 1.9/5.

    RE-RL Tuner

    Reported human rating: approximately 3.58/5.

    MusicGen

    Reported as strong among compared baselines for KL divergence and CLAP, and slightly worse than Noise2Music on FAD.

    Important limitation

    Different studies use different metrics and datasets, so direct comparison is difficult. Human evaluation remains important for quality and creativity.

    Results & accuracy methodology

    How generated music is evaluated

    Music generation is a generative task, so this research does not use one classification-style accuracy percentage. Each study evaluates a different property of the generated music and should be interpreted within its original dataset, task, and metric.

    Distribution similarity

    FID, FAD, KL divergence, and MMD compare generated and real-data distributions. Lower values generally indicate that the generated distribution is closer to the reference data.

    Musical consistency

    Pitch consistency checks whether generated pitches follow expected behavior. Duration consistency checks whether note lengths remain musically coherent.

    Prompt relevance

    CLAP measures alignment between generated audio and a text prompt. Inception Score estimates sample quality and diversity, although the review notes limits when applying image-oriented metrics to music.

    Human evaluation

    Listeners rate quality, realism, creativity, structure, diversity, musical consistency, or prompt relevance, often on a 1-to-5 scale.

    Reported results from the review

    Symbolic diffusion

    Pitch consistency reached 99% for unconditional generation and 97% for infilling. Duration consistency reached 96% unconditional and 97% for infilling. Reported FID was 0.0166 and MMD was 0.0018.

    WaveGAN

    Reported Inception Score was 4.67 ± 0.01, human recognition was 58%, and human quality was 2.3/5.

    SpecGAN

    Reported Inception Score was 3.71, human recognition was 66%, and human quality was 1.9/5.

    RE-RL Tuner

    Reported human rating was approximately 3.58/5, showing the importance of listener evaluation for generated music.

    MusicGen

    The review reports strong results among compared baselines for KL divergence and CLAP, with slightly weaker FAD than Noise2Music.

    How to state the result

    The correct conclusion is that there is no single accuracy value. Results depend on the model, representation, dataset, generation task, metric, and human evaluation protocol.

    CivicVision: smarter civic issue management

    CivicVision is a proposed multimodal AI and civic analytics platform for managing public complaints. Citizens submit text, images, and location data; the system classifies the issue, prioritizes it, detects duplicates, routes it to a department, and turns the growing complaint stream into actionable city analytics.

    01

    The civic problem

    Traditional complaint systems store submissions but leave classification, routing, duplicate detection, and city-level pattern discovery largely to manual processes.

    02

    The multimodal approach

    CivicVision combines NLP for complaint text, MobileNetV2 transfer learning for images, coordinates for geographic context, and NoSQL documents for flexible complaint records.

    03

    The analytics outcome

    Kafka and Spark extend the platform from complaint management into streaming, department analysis, hotspot detection, resolution prediction, and future complaint forecasting.

    How it was implemented

    From citizen report to civic insight

    The system is organized as a multimodal event pipeline. Each layer produces structured information that supports the next decision while keeping storage, AI inference, streaming, analytics, and presentation responsibilities separate.

    1. 01

      Collect a multimodal complaint

      A citizen submits a description, an optional image, GPS coordinates or locality, and basic complaint metadata through the web or mobile interface.

      React · HTML5 · JavaScript · FastAPI
    2. 02

      Understand the complaint text

      Text preprocessing cleans the description and converts it into features. TF-IDF with Logistic Regression, SVM, Naive Bayes, or Random Forest can classify categories such as garbage, road damage, water, electricity, drainage, traffic, and street lights.

      NLP · TF-IDF · Scikit-learn
    3. 03

      Classify the complaint image

      The image is resized, normalized, and augmented before a CNN or MobileNetV2 model predicts visual classes such as garbage, road damage, flooding, water leakage, drainage, or street-light problems.

      TensorFlow / Keras · CNN · MobileNetV2 · Transfer learning
    4. 04

      Combine AI signals and route the case

      Text category, image category, location, severity keywords, affected people, and prior complaints are combined to assign priority and recommend the responsible municipal department.

      Feature fusion · Random Forest · XGBoost
    5. 05

      Detect duplicate complaints

      TF-IDF cosine similarity is combined with category and geographic distance. A high similarity score can flag reports about the same civic incident instead of creating unnecessary duplicate work.

      Cosine similarity · Geospatial matching
    6. 06

      Store flexible complaint documents

      MongoDB stores the description, image reference, user, coordinates, AI predictions, confidence, status, timestamps, comments, and resolution history in a flexible document. Neo4j can model relationships between citizens, complaints, localities, categories, and departments.

      MongoDB · MongoDB Atlas · Neo4j
    7. 07

      Stream and process events

      Kafka topics can carry complaints, images, status changes, predictions, and notifications. Spark or PySpark processes larger datasets for category trends, department performance, monthly growth, and peak complaint periods.

      Apache Kafka · Apache Spark · PySpark
    8. 08

      Predict and visualize civic patterns

      DBSCAN identifies geographic hotspots, Random Forest or XGBoost predicts priority and resolution time, and LSTM can forecast future complaint volume. The authority dashboard presents status, trends, high-risk areas, and predictions.

      DBSCAN · XGBoost · LSTM · Plotly · Power BI

    Technologies and methodology

    Engineering choices behind CivicVision

    Multimodal AI

    Text, image, and location are used together so the system can understand both what the citizen reports and where the issue occurs.

    NoSQL data modeling

    MongoDB handles changing complaint fields naturally, while Neo4j is an optional graph layer for relationships among localities, departments, categories, and repeated issues.

    Big data streaming

    Kafka provides an event layer for near-real-time processing, while Spark supports distributed analytics across large complaint histories.

    Supervised learning

    Text and image classifiers are trained and compared using labeled civic examples. Priority and resolution-time models use complaint and operational features.

    Geospatial analytics

    DBSCAN groups nearby complaint coordinates to reveal hotspots such as localities with unusually high issue density.

    Predictive governance

    Historical complaint counts and resolution records support forecasts that help authorities respond before recurring problems grow.

    Deployment and tooling

    Python, FastAPI, Uvicorn, Docker, Git, MongoDB Atlas, Jupyter, Streamlit, Plotly, and Power BI support development, deployment, analysis, and reporting.

    Optional CivicAI assistant

    An LLM with retrieval-augmented context can explain complaint status and service rules, but it remains an optional module rather than the core research contribution.

    Results and accuracy

    Evidence, baselines, and honest reporting

    CivicVision's own results must be measured after training its selected dataset. The available reference paper reports image-classification performance for 5,494 images across four categories; those results are reference benchmarks, not CivicVision results.

    Reference dataset

    The paper used 5,494 images across Damaged Road, Flood, Trash, and Homeless People, with 85% used for training and the remaining images for testing.

    Reference test result

    The reported test counts were 813 correct classifications out of 826 test images, giving a calculated overall accuracy of approximately 98.43%.

    Reference class results

    Damaged Road: 99.38%. Flood: 97.75%. Trash: 98.35%. Homeless People: 98.36%.

    Methodology for CivicVision evaluation: split collected data into training, validation, and test sets; compare TF-IDF text models; compare CNN and MobileNetV2 image models; report accuracy, precision, recall, F1-score, confusion matrices, and ROC-AUC where appropriate.

    For resolution-time prediction, report MAE and RMSE. For hotspot clustering, report cluster quality such as silhouette score. For complaint forecasting, report time-series error. These measurements must be calculated from CivicVision's own labeled data rather than copied from the reference paper.

    The key research result is therefore a comparative evaluation across text classification, image classification, priority prediction, resolution prediction, duplicate detection, hotspot analysis, and forecasting, not one unsupported accuracy number.

    Featured case study

    Multimodal emotion detection from face and speech

    This deep-learning project recognizes emotion by combining facial expressions from a camera with speech characteristics from a microphone. The two modalities provide complementary signals, making the prediction more robust than relying on only a face or only a voice.

    01

    The challenge

    Facial emotion can be affected by lighting, pose, blur, and occlusion, while speech emotion changes with noise, microphones, accents, and speaking style.

    02

    The multimodal solution

    Facial and speech models learn separate embeddings, irrelevant features are reduced with Chi-Square selection, and the selected features are fused for final emotion classification.

    03

    The result

    The reference architecture improves recognition by combining modalities rather than asking one signal to explain every emotional state on its own.

    How it was implemented

    From camera and microphone to emotion

    The system is built as two synchronized processing branches. Each branch extracts a modality-specific representation before feature selection, fusion, and final classification.

    1. 01

      Capture both modalities

      The camera provides video frames and the microphone provides a speech signal. The system keeps the facial and audio streams associated with the same observation window.

      OpenCV · SoundDevice / PyAudio · Python
    2. 02

      Preprocess the face frames

      OpenCV detects the face, crops the relevant region, resizes and normalizes it, and can apply augmentation for changes in lighting, pose, blur, and occlusion.

      OpenCV · MTCNN / RetinaFace / MediaPipe
    3. 03

      Extract facial embeddings

      A CNN or transfer-learning model such as ResNet, EfficientNet, or Inception-ResNet-v2 learns high-level patterns from eyes, mouth, eyebrows, facial muscles, and overall expression.

      TensorFlow / Keras · CNN · Inception-ResNet-v2
    4. 04

      Prepare the speech signal

      The audio is loaded and converted into time-frequency features such as MFCC, mel spectrogram, chroma, spectral contrast, and zero-crossing rate.

      Librosa · MFCC · Mel spectrogram
    5. 05

      Learn speech emotion over time

      A CNN extracts local acoustic patterns from the spectrogram, while an LSTM or Bi-LSTM learns temporal information across the speech sequence. The reference architecture uses two convolution layers, max pooling, and a 256-dimensional LSTM output.

      CNN-LSTM · LSTM / Bi-LSTM · ReLU
    6. 06

      Reduce redundant features

      Chi-Square feature selection measures the relationship between features and emotion classes, removing lower-value or redundant signals before fusion.

      Chi-Square · Feature selection
    7. 07

      Fuse the two embeddings

      The facial and speech feature vectors are concatenated or combined through feature-level or decision-level fusion. The fused representation contains visual and acoustic evidence together.

      Feature fusion · Multimodal learning
    8. 08

      Classify and display the emotion

      A Softmax, dense neural network, SVM, or LIBSVM classifier predicts Happy, Sad, Angry, Fear, Disgust, or Neutral and returns the final label with evaluation scores.

      LIBSVM · Softmax · FastAPI / Flask · HTML / CSS / JavaScript

    Technologies and methodology

    Algorithms behind the model

    Computer vision

    OpenCV handles camera input, frame extraction, face detection, cropping, resizing, normalization, and visual preprocessing.

    Audio signal processing

    Librosa converts speech into MFCC, mel-spectrogram, chroma, spectral, and zero-crossing features suitable for deep learning.

    Deep feature learning

    CNN and Inception-ResNet-v2 learn facial patterns, while CNN-LSTM learns local speech features and temporal voice information.

    Traditional ML baselines

    Logistic Regression, Random Forest, SVM, KNN, and Decision Tree can provide comparison baselines before the multimodal deep model.

    Fusion strategies

    Feature-level fusion combines embeddings before classification; decision-level fusion combines modality predictions at the output stage.

    Emotion classes

    The practical classifier can recognize Happy, Sad, Angry, Fear, Disgust, and Neutral, subject to the labels available in the selected dataset.

    Datasets

    RAVDESS and CREMA-D support audiovisual emotion research. MELD and MOSI provide multimodal video, speech, and emotion annotations used in the reference study.

    Application stack

    Python, TensorFlow/Keras or PyTorch, OpenCV, Librosa, FastAPI or Flask, and a browser interface support training, inference, and presentation.

    Results and accuracy

    Reference performance and honest evaluation

    The figures below come from the supplied research paper. They are reference benchmarks, not results from this portfolio implementation. Your own accuracy should be reported only after training and testing your selected dataset.

    Unimodal comparison

    Voice recognition: 83.72%. Video or facial recognition: 80.19%. Multimodal recognition: 88.64%.

    Dataset results

    Reported overall accuracy was 87.56% on MOSI and 90.06% on MELD for the proposed multimodal architecture.

    Facial features

    Fully connected features from Inception-ResNet-v2 produced the strongest facial feature recognition rate reported in the study: 85.75%.

    Emotion-level results

    Happy: 90.89%. Angry: 91.26%. Disgust: 76.72%. Sad: 87.13%. Fear: 89.28%.

    Feature-selection result

    The study reports that adding Chi-Square feature selection improved multimodal recognition by approximately three percentage points in its experiment.

    Evaluation methodology

    For your own model, report training, validation, and test accuracy with precision, recall, F1-score, and a confusion matrix. Compare face-only, speech-only, and fused models.

    Real-world evaluation should also record per-class performance because emotions such as fear, sadness, and disgust can be confused. Report lighting, occlusion, background noise, accents, and class balance as limitations.

    The professional conclusion is that multimodal fusion is more informative than either modality alone in the reference experiment, but your project’s final accuracy must come from your own trained and tested implementation.

    Results and analytical output

    Questions the dashboard answers

    This project is an analytics and visualization workflow, so its results are insights and validated metrics rather than a single classification accuracy percentage.

    Team performance

    Compare matches played, wins, losses, win percentage, average score, total runs, and performance changes across seasons.

    Player performance

    Rank batters by runs, average, strike rate, boundaries, and sixes, and compare bowlers by wickets, economy, average, overs, and dot balls.

    Match and toss analysis

    Study toss decisions, toss winner versus match winner, winning margins, highest-scoring games, closest matches, and match distribution.

    Venue and season trends

    Identify venues with higher scoring patterns, compare season-wise run and wicket trends, and explore how conditions relate to outcomes.

    Dashboard KPIs

    Total matches, seasons, teams, players, runs, wickets, wins, win percentage, strike rate, and economy rate provide a fast project overview.

    Insight generation

    The final conclusions are based on the actual dataset, SQL results, Python exploration, and Power BI filters rather than unsupported assumptions.

    Evaluation approach: validate row counts and totals after cleaning, cross-check SQL aggregates against Python calculations, verify Power BI relationships and measures, and document the filters behind each insight.
